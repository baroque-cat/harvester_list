## 4.2 Новая конфигурационная поверхность (секция `persistence:`)

| Ключ | Дефолт схемы | Смысл |
|---|---|---|
| `snapshots_enabled: bool` | **False** | мастер-выключатель периодических И финальной сборки. Осознанная смена дефолта (единственная в программе, §1.3.2 доков): производный артефакт с нулём потребителей и квадратичным churn; пинов нет; боевой прод-конфиг получает явный `false` (инвариант 5 — политика видима) |
| `snapshot_interval_s: int` | 3600 | НАКОНЕЦ парсится loader'ом (мёртвый ключ оживает); валидация >0; учитывается только при enabled |
| `snapshot_keep_last_n: int` | 3 | ротация: после сборки удаляются все кроме N последних поколений (поколение = полный набор {type}.json одного build; 0 = хранить все). Удаление громкое (INFO со счётчиком байтов) |
| `snapshot_final_max_bytes: int` | 2·10⁹ | size-guard финальной сборки: если суммарный объём шардов выше — финальная сборка ПРОПУСКАЕТСЯ с однократным WARNING (защита graceful stop даже при включённых снэпшотах); при disabled не применяется |

Валидация: новый `_validate_persistence_config` (E1) — позитивность всех числовых ключей секции + WARNING на неизвестные ключи секции (прецедент dead-key warnings `loader.py:600-640`); зеркальные сообщения в schema `__post_init__` и validator байт-в-байт (дом-паттерн).

## 4.3 Улучшения сборки (при enabled=true; при off — недостижимы)

1. **Инкрементальность**: сливать только шарды с `last_ts` новее маркера последней сборки (хранится в sidecar `snapshots/.build_meta.json`: ts, список учтённых shard-файлов). Sidecar-индексы УЖЕ существуют (`snapshot.py:31-51`) — механизм чтения не меняется, добавляется фильтр входа. Полная пересборка — при отсутствии/несовместимости маркера (громко).
2. **Компактность**: убрать `indent=2` (−1.5–2.5×); формат остаётся валидным JSON (совместимость с гипотетическим внешним потребителем сохраняется).
3. **Атомарность** сохраняется: `.tmp`+rename как сегодня.

## 4.5 Пины и гейт

Пины (новый `tests/test_snapshot_lifecycle.py`): C1 флаг off ⇒ ни одной сборки (периодика и финал); C2 on ⇒ сборка есть, интервал уважается (fake clock); C3 ротация keep-last-N (N+1-я сборка удаляет старейшую, счётчик байтов в логе); C4 инкрементальность (второй build читает только новые шарды — spy на списке входа); C5 size-guard (финал пропущен + WARNING при превышении); C6 loader парсит все четыре ключа, absent → дефолты; C7 валидатор: негативы отвергнуты зеркальными сообщениями; C8 compact JSON без indent (структурный); C9 простой режим (`format: txt`) неизменен байт-в-байт (guard существующего поведения).

Живой гейт (волна 1): короткий soak 120 с с `false` — ноль строк «Built snapshot», stop-time сравним с прежним минус сборка; контрольный soak 120 с с `true, interval 60, keep_last_n 2` — сборки появляются, ротация держит 2 поколения. Компараторы: идентичность Н9.4 не затрагивается (снэпшоты вне конвейера задач).
