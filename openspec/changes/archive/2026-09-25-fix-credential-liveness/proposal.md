# Proposal: fix-credential-liveness

## Why

The credential layer can sleep forever inside a claimed task and benches healthy keys on false positives. Verified in live code (2026-09-25):

1. **Unbounded waits.** `Credentials._get_available` (`tools/credential.py:126-154`) contains two infinite paths: `while True` + `time.sleep(wait)` with no deadline and no iteration counter, and a 0.1 s spin when `next_wait() <= 0`. Since the sqlite-queue promotion (R2), any in-task sleep longer than `queue.visibility_timeout_s` (300 s) guarantees duplicate execution — the credential cooldown maximum is 900 s (`GITHUB_CREDENTIAL_COOLDOWN_MAX`), three times the window, and `storage/task_queue.py` has no claim-renewal API. Search workers (`stage/definition.py:246-315`) rotate credentials inside `while True` loops that can sleep up to 900 s per rotation inside a claim.
2. **No early release.** `GithubCredentialState.mark_success` (`tools/state.py:80-89`) clears a cooldown only if it has already expired. One false positive from the broad content detectors (`please wait`, `try again later` — `search/client.py:527-550`) benches a perfectly working credential for the full escalated term (60→120→240→480→900 s), and with four tokens the "all cooling" state — and therefore the infinite `_get_available` loop — becomes reachable in normal operation.
3. **Detected signal is discarded.** `_extract_wait` already reads `Retry-After` and `X-RateLimit-Reset` (`client.py:647-666`), but primary quota exhaustion (scope = token, exact reset known) and secondary/abuse limits (scope = subject, pressure makes it worse) collapse into one `mark_limited` call. The reaction cannot be right for both.
4. **Dead adaptive knobs.** `RateLimitConfig.calculate_adjusted_rate` (`core/models.py:258-269`) has never been called in repository history (pickaxe: born dead in `3f43528`). `backoff_factor` / `recovery_factor` / `max_rate_multiplier` / `min_rate_multiplier` parse and validate but do nothing; comments in `config.yaml` and `examples/config-full.yaml` describe behavior that does not exist. The live model is `TokenBucket.adjust_rate` (`core/models.py:721-746`).

R5.1 moved gather to raw transport and added the DEFER outcome (bounded `RateLimitDeferral` → `defer_task`, attempts unchanged). The search/repo_meta paths still ride the credential layer as-is. This change makes the credential layer live-safe: bounded waits, honest release, differentiated limit reactions — without which raising governor caps converts freed RAM headroom into quota burn and silent duplicate execution.

## What Changes

- **Bounded credential selector.** `_get_available` computes a deadline BEFORE every sleep (config `credential_liveness.max_wait_s`, cross-validated `< queue.visibility_timeout_s` under sqlite, pattern of the R5.1 D5 invariant). Both infinite paths (blocking loop and 0.1 s spin) are removed. On exhaustion the selector raises a new typed `CredentialsExhausted` exception — never returns `None` (None means "no credentials configured" and the search worker today conflates it with an honest empty result: `return [], "", 0`).
- **Search stage routes exhaustion to DEFER.** The credential-rotation loops in `_execute_first_page_search` / `_execute_page_search` catch `CredentialsExhausted` and defer the task via the existing R5.1 seam (`defer_task`: attempts/created_at/dedup_id preserved, `tasks_deferred` counted, bounded stage pause, no registry writes). Never dropped, never completed-empty, never sleeping inside a claim past the budget.
- **Early cooldown release on success.** `mark_success` clears the credential's cooldown entry immediately (evidence: a success proves the credential works), resetting the escalation ladder. Rollback flag `credential_liveness.early_release: true|false`.
- **Primary vs secondary limit reactions.** `mark_limited`/`mark_credential_limited` carry a limit kind derived from the ALREADY-read signals: header-anchored wait (`Retry-After`, `X-RateLimit-Reset` + `remaining: 0`) → primary (scope = token): cool that credential until reset, wait is bounded by the selector budget. Secondary markers (`secondary rate limit`, `abuse detection`) or 403/429 without usable headers → secondary (scope = subject): cool the whole service pool, loud ERROR once per episode, stage-level pause, dedicated counter. Cross-service budgets stay separate (a single global brake turns partial degradation into a full stop — Ф4).
- **Narrowed content detectors.** Broad phrases `please wait` / `try again later` are removed from `is_rate_limited_content` and `_is_http_rate_limited` (keeping verifiable GitHub markers: `rate limit`, `secondary rate limit`, `abuse detection`, and the existing web-specific `Search failed. Please try again later.`). Ambiguous text is treated as a transient task failure (bounded requeue, counted), NOT as a credential limit.
- **Full-bench emergency state.** K consecutive exhaustion episodes on one service (config `credential_liveness.emergency_threshold`, default 3) → stage emergency: loud ERROR, counter, one log line per episode (degrade-once-per-kind house pattern). Existing bounded-requeue and loud-drop paths (`stage/base.py:327-334`) preserved without weakening.
- **BREAKING (config): dead adaptive coefficients removed.** `backoff_factor`, `recovery_factor`, `max_rate_multiplier`, `min_rate_multiplier` and `calculate_adjusted_rate` are deleted; the loader emits a one-time loud WARNING and IGNORES these keys when present (graceful acceptance period — operator configs must not crash); the validator stops range-checking them. `config.yaml`, `examples/config-full.yaml` and README comments are corrected to describe the real `TokenBucket.adjust_rate` behavior (×0.5 after 3 consecutive failures, floor 0.1×base; ×1.1 after 10 consecutive successes, cap 2×base).
- **Observability.** New counters on the existing metrics surface (house pattern `core/metrics.py`): exhaustion episodes, deferred-by-credentials tasks, secondary-limit incidents, early-release events, emergency trips. All surfaced through PipelineStatus.

Not in scope: claim-renewal API for the sqlite queue (R5.1 D5 deferred it; this change instead guarantees no in-task sleep exceeds the window), cross-SERVICE subject escalation (documented as a follow-up candidate), restoring `file_commit_date` (separate task per plan Ф4/R5.1 D7).

## Capabilities

### New Capabilities
- `credential-liveness`: bounded-wait credential selection with typed exhaustion, early cooldown release on success, primary/secondary rate-limit differentiation in the reaction, narrowed content detectors, full-bench emergency state, credential observability counters, and the config surface (`credential_liveness:` section) with cross-section invariants.

### Modified Capabilities
- `failure-handling`: the "Existing protections are preserved" requirement's full-pool-cooldown scenario changes from "blocks until the earliest cooldown release" to "waits at most the configured budget, then the task DEFERS (attempts unchanged, counted, never dropped, never completed-empty)". The never-drops / never-completed-empty guarantees are preserved verbatim.

## Impact

- **Code:** `tools/credential.py` (selector rewrite), `tools/state.py` (`CredentialsExhausted`, limit kind, early release), `search/client.py` (`mark_credential_limited`, `is_rate_limited_content`, `_is_http_rate_limited`, `_gather_credential` rest-path catch), `stage/definition.py` (search rotation loops → DEFER routing), `storage/repo_meta.py` (`_next_credential` catches `CredentialsExhausted` → existing silent-yield semantics preserved), `manager/task.py:417-418` (startup capability probe must not crash or sleep), `core/models.py` + `config/loader.py` + `config/validator.py` + `config/schemas.py` (dead coefficients out, `credential_liveness:` section in), `core/metrics.py` (counters).
- **Behavioral pin at risk:** `tests/test_fh_protections.py::test_s16_full_pool_cooldown_waits_never_drops` pins the OLD unbounded-blocking contract; it is deliberately REPLACED (never weakened) by bounded-wait→deferred-exhaustion pins. `test_aux_backoff_schedule_unchanged` survives (escalation on repeated `mark_limited` is unchanged).
- **Specs:** new `credential-liveness`; delta on `failure-handling`.
- **Configs:** live `config.yaml` gains a `credential_liveness:` section; dead per-provider `rate_limit:` keys become warn-and-ignore; `examples/config-full.yaml` + README updated. Rollback: `credential_liveness.wait_mode: bounded|blocking` (blocking = byte-for-byte old selector behavior) + `credential_liveness.early_release: false`.
- **Docs:** this change ships a `runbook.md` (referenced from tasks.md group 9) that the executor runs AFTER code+tests are green — a single consolidated live gate closing BOTH this change's acceptance AND the still-open operator-gated R5.1 gates 8.1 (full soak) / 8.2 (rollback drill) / 8.3 (secondary-limit accounting, organically observed only).
