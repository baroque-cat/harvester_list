## 3. Exception, constants and client transport layer (gather-transport S4–S7, S9–S16, S19, S20; failure-handling S18; date-extraction S13 pin drivers)

- [x] 3.1 `core/exceptions.py`: add `RateLimitDeferral(NetworkError)` — deliberately a SIBLING of `TransientFetchError`, not a subclass of `ConnectionError`, so `RetryCore.should_retry_error` (`tools/retry.py:51-67`) never auto-retries it and no existing `except TransientFetchError` handler can collapse a deferral into a failure-empty (fh-S18 taxonomy). Constructor: `(message, wait_s: float = 0.0, stage_pause: bool = False, **kwargs)` storing both fields.
- [x] 3.2 `constant/system.py`: `SERVICE_TYPE_GITHUB_RAW: str = "github_raw"` beside the existing pair; extend `GitHubClient._service()` (`search/client.py:276-287`) to recognize `raw.githubusercontent.com` → `SERVICE_TYPE_GITHUB_RAW` (branch BEFORE the `"github.com"` substring test; note `githubusercontent.com` does not contain `github.com`, which is exactly why today's fall-through yields `None` and zero throttling — D3). Add a `github_raw` entry to the `Config.__post_init__` default ratelimits (`base_rate=2.0, burst_limit=4, adaptive=True` — polite against the measured latency-bound 3.03 req/s ceiling); operators override via the top-level `ratelimits:` section like the other two.
- [x] 3.3 `search/client.py` address derivation (D2): `derive_raw_url(blob_url) -> Optional[str]` — parse `owner/repo/ref/path` from `https://github.com/<owner>/<repo>/blob/<ref>/<path>` tolerating `?plain=1` and `#L…` suffixes; a `[0-9a-f]{40}` ref is emitted verbatim as `https://raw.githubusercontent.com/<owner>/<repo>/<ref>/<path>` (S4); any other ref falls back to `HEAD`, increments `head_fallback` and logs one WARNING naming the link (S5); unparseable/non-blob/empty/`None` input returns `None`, increments `unparseable_link` and NEVER raises (S7); the function never reads or accepts a blob content hash — the `item['sha']`-as-ref trap is pinned by S6 against the captured sample. Add `gather_target_url(url, transport)` router: `html` → the discovered URL unchanged, `raw` → `derive_raw_url`, `rest` → `https://api.github.com/repos/<owner>/<repo>/contents/<path>?ref=<ref>` form (same ref rules incl. HEAD fallback).
- [x] 3.4 `search/client.py` observability (S21): module-level counters with `reset_gather_transport_stats()` / `get_gather_transport_stats() -> Dict[str, int]` mirroring the `get_date_parse_stats()` house shape; exact keys: `requests_raw, bytes_raw, requests_html, bytes_html, requests_rest, bytes_rest, deferred_rate_limit, deferred_secondary, dropped_auth, dropped_not_found, head_fallback, unparseable_link, truncated`. A refused request still counts as an issued request (`requests_*`), and `bytes_*` accumulates delivered payload bytes per transport. The key set is declared once as `_GATHER_TRANSPORT_STAT_KEYS` and every counter exists from import time, so a single-transport run publishes the SAME schema as a mixed one (no mid-run widening); `reset_gather_transport_stats()` restores exactly that set and an undeclared counter is refused with a WARNING instead of silently widening the surface. *(Amended during verification W1: the original 11-key list omitted `bytes_html`/`bytes_rest`, which contradicted both README's `bytes_{raw,html,rest}` promise and S21's "per transport" requirement.)*
- [x] 3.5 `search/client.py` fetch helper (D4/D5/D6/D8): `fetch_gather_content(url, transport="raw", max_payload_bytes=8*1024*1024, max_refusal_wait_s=60.0, retries=3, timeout=10) -> str`. Resolve the target via `gather_target_url`; an unresolvable address raises inside the existing `TransientFetchError` family with ZERO requests issued (S7). Throttle attribution only when the module singleton `_github_client` already exists (tests stub both ways; never lazily construct inside the helper): `raw` → `_limit/_report` under `github_raw` with `credential=None` (S9: exactly one acquire before send and one report after, success True on 2xx / False on 5xx), `html` → `github_web`, `rest` → `github_api` with a token from the credential provider (S10/S11 budget isolation). Read responses in chunks aborting past `max_payload_bytes`: increment `truncated`, keep the prefix as valid extraction input, do NOT treat as failure (S20/D8); `rest` additionally base64-decodes the JSON `content` field. Refusal classification is signal-based using the class client's existing judgment (`_is_http_rate_limited` markers, `_wait_from_headers` for `Retry-After`/`X-RateLimit-Reset`): body matching `secondary rate limit|abuse detection` → `RateLimitDeferral(wait_s=min(published_or_cap, max_refusal_wait_s), stage_pause=True when no finite wait published)` + one loud ERROR + `deferred_secondary` (S12, S16 — exactly ONE request issued, traffic stops immediately); otherwise 429/403-rate-limited with a published finite wait → `RateLimitDeferral(wait_s=min(signalled, max_refusal_wait_s))` + `deferred_rate_limit` (S15 incl. the 900→cap clamp, D5 runtime bound); 401 or 403 WITHOUT rate-limit markers → terminal after a single attempt: WARNING + `dropped_auth`, raised in the `TransientFetchError` family and explicitly NOT a `RateLimitDeferral` (S13 — this is the misclassification fix; reuse the marker regex, do not touch the shared detectors globally); 404 → terminal single attempt + `dropped_not_found` (S14); timeout/5xx/connection reset → bounded inner retries then `TransientFetchError`, every attempt reported False to the bucket (S9 failure pin). The legacy module-level `http_get` stays byte-for-byte intact for all non-gather callers.

## 4. Stage DEFER path (gather-transport S8, S18; failure-handling S19–S21)

- [x] 4.1 `stage/base.py`: add `defer_task(task) -> bool` — the third outcome seam (D4). It bypasses the dedup gate entirely (a deferral is not a duplicate; `put_task`'s attempts==0 rejection must not apply), preserves `task.attempts` UNCHANGED, and preserves the ORIGINAL `created_at` and `dedup_id` (durable branch passes all three through to `SqliteTaskQueue.put`, keeping the `max_age_hours` age gate anchored to first creation — fh-S20's ceiling). Memory branch: plain `queue.put(task, timeout=1.0)`; `queue.Full` → loud WARNING + counted drop, storage errors increment `tasks_dropped_backend_errors` exactly like `put_task`. Increments `tasks_deferred` and logs one WARNING per episode naming stage/provider/task and the bounded wait. *(Amended during verification W2: the WARNING originally omitted the wait, which is computed in `_worker_loop`; `defer_task` now takes an optional `wait_s` — the already-clamped value passed by the worker — and names both the effective wait and the cap it hit, via the extracted `_defer_wait_cap()` helper. Plain re-queue callers that omit `wait_s` stay valid and log `bounded wait: n/a`.)*
- [x] 4.2 `stage/base.py` `_worker_loop`: insert `except RateLimitDeferral as d` BEFORE the generic `except Exception` retry branch: sleep `min(d.wait_s, effective cap)` inside the claim (bounded by construction — the D5 invariant `WAIT_CAP < visibility_timeout_s` is config-enforced in 2.3 and runtime-clamped in 3.5); when `d.stage_pause` is True also set a bounded stage-wide pause gate so sibling workers stop claiming new rows for the same bounded interval (S16 stage-level effect); then `self.defer_task(task)`. Accounting: NO `total_errors`, NO `tasks_requeued`, NO `total_processed` for the deferral itself (a deferral is not a completion — fh-S19); the `finally` clause still acks the original claim so the row is never double-delivered (S18).
- [x] 4.3 `stage/base.py` `process_task`: explicit `except RateLimitDeferral: raise` placed before the `except TransientFetchError` branch, so a deferral is never swallowed by `_handle_processing_error`, never counted by `_detect_failure_empty`, and never mode-collapsed in ANY `failure_handling` mode (the taxonomy SHALL is unconditional — fh-S18/S21).
- [x] 4.4 `stage/definition.py` `_acquisition_worker`: pass the configured gather transport into `client.collect(...)` (from `resources.config.gather`); add `except RateLimitDeferral: raise` around the collect call BEFORE the existing `TransientFetchError` branch — a deferral records NO gather outcome at all: no `_record_gathered(success=False)`, no `visit_status` transition, no coverage row (fh-S21), and the outer catch-all `except Exception` must not see it either (it would record a false failed gather).
- [x] 4.5 `core/metrics.py` `StageMetrics`: add `tasks_deferred: int = 0` beside `tasks_requeued`/`tasks_dropped_max_retries`; wire it in `BasePipelineStage.get_stats()`.
- [x] 4.6 Drive `tests/test_gt_stage_integration.py` green: S8 (persisted rows survive a transport flip byte-for-byte; recovered backlog processes under the new transport; sqlite file never migrated), S18 (repeatedly deferred row is claimed by exactly one worker at a time, `sweep_expired_claims() == 0` while workers sleep bounded waits, final execution count exactly 1 after ack — the repaired consumer defers via `stage.defer_task`), S21 (flat integer stats surface with the exact key set).
- [x] 4.7 Drive the appended failure-handling pins green: `test_fh_stage_modes.py::test_s19_*` (strict-mode worker loop: defer→success leaves `attempts==0`, `tasks_requeued==0`, `tasks_dropped_max_retries==0`, `total_errors==0`, `tasks_deferred==1`, `total_processed==1`) and `::test_s20_*` (deferred row keeps its original `created_at`; reopen purges it loudly via the existing age gate — deferral circulates bounded by `max_age_hours`, never by the retry budget); `test_fh_gather_fidelity.py::test_s21_*` (deferred gather writes no links row and no coverage row; contrast with the untouched s7 failed-fetch pin).
