# Proposal: fix-gather-transport

## Why

The gather stage fetches file content through an anonymous `github.com` blob-HTML path that sits **outside every throttling mechanism the project has built**: module-level `http_get` (`search/client.py:746`) never calls `limiter.acquire()`, sends no credential (`DEFAULT_HEADERS` carries only `Accept`, `constant/system.py:87-89`), never reports outcomes to adaptive buckets, and ignores `Retry-After`. The measured cost over a 600 s production-shaped soak on 2026-09-22 was **2 715 `Rate limit exceeded (HTTP 429)` refusals**, a gather backlog of **2 343 tasks**, and 1 117 ERROR lines — while the search stage, which *is* throttled and credentialed, ran clean. Each doomed task burns **12 HTTP requests and ~27 s of a blocked worker** before it is dropped. Separately, HTTP 403 is misclassified as `NetworkError("Authentication failed")` (`client.py:824-826`), which `RetryCore.should_retry_error` does not retry (`tools/retry.py:51-67`): such a task makes **one** request, is never requeued, and is not even counted in `tasks_dropped_max_retries` — a silent loss channel, and GitHub secondary limits routinely arrive as 403, so the 429 figure understates the problem.

Live measurement on 2026-09-25 shows the transport itself is the cheapest large lever available: for the same real files, anonymous blob HTML costs a mean of **523 KiB per file** versus **17.1 KiB** from `raw.githubusercontent.com` — **30.6× less traffic** — applied to the observed 2 343-task backlog that is **1.20 GiB → 39 MiB**.

## What Changes

- New config section `gather.transport: html | raw | rest` (default **`raw`**), resolved per run; rollback is a flag flip, never code removal. `html` reproduces today's behavior byte-for-byte.
- Blob→raw URL derivation from the link the search stage already produced, using the **exact 40-hex commit ref** parsed out of the blob URL. Live capture proves this is unambiguous and proves the obvious wrong answer is fatal: `item['sha']` from `/search/code` is the **blob** SHA and returns HTTP 404 when used as a raw ref. A ref that is not a 40-hex SHA falls back to `HEAD` and is counted, never guessed silently.
- Gather requests routed through the shared `GitHubClient` so they acquire limiter tokens and report success/failure like every other GitHub caller — under a **separate rate-limit resource class per transport**, so gather can never consume the `code_search` budget (measured at exactly **10/min** per token).
- Correct refusal classification on the gather path: 403 carrying rate-limit markers is a rate-limit refusal, not an authentication failure; `Retry-After` and `X-RateLimit-Reset` are honored instead of ignored. Behavior of the already-working `search` and `repo_meta` paths is pinned unchanged.
- Three refusal outcomes kept strictly distinct — **DEFER** (row returns to `pending` with `attempts` unchanged, plus a bounded stage pause), **BOUNDED REQUEUE** (existing, `attempts++`, cap 3, test-pinned), **LOUD DROP** (existing, counted). Conflating defer with requeue would burn the entire backlog at 12 requests per task.
- Hard safety invariant `WAIT_CAP < queue.visibility_timeout_s`: no gather worker may sleep inside a claimed durable-queue row longer than the visibility window, because `storage/task_queue.py` exposes no claim-extend API and an expired claim is re-delivered to another worker. The current 900 s cooldown ceiling (`constant/system.py:49`) against a 300 s visibility timeout violates this today.
- New observability: per-transport bytes and latency, refusals split by class (primary quota / secondary-abuse / auth / not-found), deferrals, `HEAD`-fallback count, and a pin that the `date_metrics` NULL share does not worsen.
- `pipeline.threads.gather` documented as a politeness parameter with an honest cost (fewer threads = slower harvest); recommended 8 → 2–4 under `html`, relaxable under `raw`.
- Docs: README section and a commented `gather:` block in `examples/config-full.yaml`.
- Explicitly OUT of scope: credential-selector liveness and the unbounded `while True` in `tools/credential.py:126-154` (that is `fix-credential-liveness`, next in sequence); global narrowing of the shared content detectors; reviving or deleting the inert adaptive knobs (`calculate_adjusted_rate` has never been called in repository history); cross-provider fetch sharing; restoring `file_commit_date` from the REST `last-modified` header; the aggregation `shadow→on` promotion.

## Capabilities

### New Capabilities

- `gather-transport`: config-selected transport for fetching gathered file content, correct derivation of the transport-specific URL from a discovered blob link, per-transport rate-limit isolation, refusal classification and the defer/requeue/drop outcome model on the gather path, and transport observability.

### Modified Capabilities

- `failure-handling`: "Bounded retry and honest accounting for failed tasks" gains the DEFER outcome (re-enqueue **without** incrementing `attempts`) as a third, distinct terminal path; "Gather-outcome fidelity" and "Empty-result taxonomy at the fetch boundary" change because a rate-limit refusal is no longer a gather *failure* recorded as `visit_status='failed'`, and because HTTP 403 with rate-limit markers stops being classified as a non-retryable authentication error.
- `date-extraction`: "File commit date from gathered blob pages" is premised on an already-downloaded **blob HTML** payload. Under `raw` there is no HTML at all, so the extraction point becomes transport-dependent and yields NULL by construction rather than by GitHub's rendering choices. The requirement's safe-degradation contract and fill-rate drift detector are preserved; the wording must stop asserting a blob-HTML source that the default transport no longer downloads.

## Impact

- **Code**: `search/client.py` (transport-aware fetch path, blob→raw derivation, 403/429 classification, limiter integration for gather), `stage/definition.py` (acquisition worker passes transport and maps refusals to defer/requeue/drop), `config/schemas.py` + `config/loader.py` + `config/validator.py` (new `GatherConfig`), `core/metrics.py` (transport counters), `manager/pipeline.py` (wiring), `constant/system.py` (per-transport service names), docs and examples.
- **Evidence base** (all live-captured, cited in design.md): `GET https://api.github.com/rate_limit` with token, 2026-09-25 → `core` 5000/h, `code_search` 10/min, `search` 30/min. Same five real files across three surfaces: HTML anonymous 738–1085 ms and 282 KB–1.27 MB with **no rate-limit headers at all**; raw anonymous 327–634 ms and 1.9–108 KB with `x-cache: MISS/HIT` and **zero** `core` consumption; REST with token 398–591 ms, 3.8–150 KB base64, full `x-ratelimit-*`, **1 `core` unit per call**. Burst of 80 distinct raw URLs with no sleeping: 80/80 HTTP 200, zero refusals, 3.03 req/s sustained (latency-bound, not rate-bound), p50 338 ms / p99 390 ms. `GET https://api.github.com/search/code?q=/sk-[a-zA-Z0-9]{32}/` with token, 2026-09-25 → item keys `{git_url, html_url, name, path, repository, score, sha, url}`; the `html_url` ref and the `url` `?ref=` parameter agree on a 40-hex commit SHA in 2/2 samples; bogus refs and `item['sha']`-as-ref both return 404 with a 14-byte body.
- **Data**: no schema changes. Registry rows, NDJSON shards and `recover_tasks()` semantics are untouched. `visit_status` keeps its existing value set; a deferred task writes no gather outcome at all.
- **Interfaces**: `collect()` already accepts `text=` and `extract()` is a pure `re.findall` with no HTML-specific logic (`client.py:1426-1456`, `:1494-1517`), so the extraction contract is transport-agnostic by construction. `AcquisitionTask.data.url` remains a blob URL on the wire — the transform happens at fetch time, keeping persisted queues and legacy snapshots valid across a transport flip.
- **Dependencies**: none added; stdlib `re` plus the existing `requests` session factory.
- **Operations**: gather traffic drops ~30× per file under `raw`; the anonymous HTML path is also *blind* (it returns no rate-limit headers, so remaining budget is unknowable and only an already-happened refusal is observable), which `rest` fixes at the price of 1 `core` unit per file. Disk and RAM footprints are unaffected (queues are already durable per `durable-task-queue`).
- **Security**: `raw` needs no credential, so this change *reduces* credential exposure on the gather path. Key material appears in fetched payloads exactly as today; the known console-redaction gap in `provider/client.py:861` is pre-existing, unrelated, and deliberately not addressed here.
